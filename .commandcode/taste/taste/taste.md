# Taste
- Prefers detailed, actionable roadmap/plan documents (task checklists with done-conditions, verification steps, and handoff criteria) written into the `docs/` folder before implementation begins. Confidence: 0.8
- Expects folder-structure diagrams and path references in docs to mirror the actual repository layout — when real directories are created/renamed (e.g., `backend/`, `frontend/`, `machine-learning/`), wants planning docs updated to match rather than keeping an invented structure. Confidence: 0.4
- For academic/college projects, explicitly keeps scope simple: explicitly excludes production-grade tooling (no Alembic migrations, Docker, auth, async jobs) and reuses existing setup (same venv, in-process model import) over adding moving parts. Confidence: 0.8
- When writing a new planning doc, mirrors the structure and style of an existing doc of the same kind (same heading levels, checklists, tables, handoff section) so all project docs stay consistent. Confidence: 0.7
- Prefers implementing in defined, scoped increments (e.g., completing a specific roadmap range such as "T0–T2") and pausing at dependency/credential boundaries to request what the user will provide (e.g., a DB connection string) rather than guessing. Confidence: 0.4
- Verifies work with real runtime checks before marking a task done — imports the module, boots the server, hits endpoints like `/health`, inspects startup logs, then kills the test server — and updates the roadmap checklist (`- [x]`) to reflect completion. Confidence: 0.6
- For well-defined milestones, prefers the agent to take full ownership and complete the work end-to-end in one shot — working independently, without asking questions or requiring mid-task intervention (e.g., "just do it in one shot without my intervention", "do it without asking me anything, independently", "work independently without user intervention"). Confidence: 0.9
- Prefers free-tier deployment options and wants paid-plan/paywall constraints verified before committing to a platform (e.g., checked whether Docker-based deployment on Hugging Face Spaces is paid-only after considering Render/Vercel free plans). Confidence: 0.8
- For demo frontends, prefers a clean light-theme, monochrome UI with a professional, Vercel-style font (Geist), kept simple for demonstration purposes. Confidence: 0.7
- Prefers Next.js when bootstrapping frontend projects. Confidence: 0.6
- Wants a single script that runs the entire app/stack for easy local startup. Confidence: 0.6
- Pushes commits directly to `main` rather than using feature branches or pull requests. Confidence: 0.4
- Wants in-repo Markdown documentation that explains the project's existing architecture: deep detail on the core subject (e.g., ML model architecture — exact model code, hyperparameters, data pipeline, results) and only a brief overview of supporting parts (e.g., backend endpoints/pipeline). Confidence: 0.6
- Wants documentation deliverables (e.g., notes files) to be self-contained and independent of other files in the codebase — no links or pointers to sibling docs/repo files; every context, number, and design decision explained inline so the doc stands alone even outside the repo. Confidence: 0.7
- Wants documentation deliverables produced as a polished PDF as well as the Markdown source (e.g., "convert it into a pdf as well"), treating PDF as a distributable companion artifact to the .md file. Confidence: 0.5
